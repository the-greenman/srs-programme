# F-drift: spec vs implementation divergences (snapshot 2026-10-08, read from origin/master / origin/main)

Method: diffed schema mirrors; compared serde structs to schemas; sampled 128 invariant records vs srs-rust; searched issues in srs, srs-rust, srs-web, srs-vscode, muDemocracy.org, semanticops.com; read srs-context findings. Confidence notes: invariant coverage is a grep heuristic (many impl checks cite no I-number), so "no enforcement found" means "none found by keyword", not proven absent.

## Headline facts
- Mirror JSON files are byte-identical to spec in srs-rust and srs-vscode (diff -rq clean). Only extras: srs-rust mirror keeps `relations-collection.json` (spec no longer has it; declared a permanently retained legacy validator, srs-rust#929) and both mirrors add a SHA256SUMS. Schema mirroring itself is healthy; the drift is in prose, serde grammars, payload schemas and client logic.
- dataModelRevision: spec corpus srs/srs = 8. srs-rust CURRENT_DATA_MODEL_REVISION = 9 (field_type_migration_service.rs:32). Revision 9 = RFC-046 (createdBy Actor on Record/Note/Relation, session-stamped; 8->9 migration changes no data), ACCEPTED (srs#850 closed), implemented srs-rust#1171. The "repository at revision 8; this build writes revision 9" message means the spec repo has not been migrated to 9, so actor-attributed writes there are refused (`revision-too-old`, RFC-046 R11). This is deliberate lag, not a bug, but CLAUDE.md still says "until then no corpus may carry it" (stale doc, see table).

## Root causes of drift
1. Three-plus parallel definitions of one model (spec prose, JSON Schema, Rust serde, client TS), with CI gates covering only some pairs (RFC-031 prose<->schema with allowlists; schema-sync mirrors; srs-rust#777 schema<->struct). Nothing links invariants to diagnostics, so spec-ahead drift is invisible (row 17).
2. Mirrors are copies refreshed after the fact: every spec change spawns N mirror/tracking issues (srs-rust#550, #787, #864, #887, srs-vscode#43/48/49/96/97/99/101/103/106/123). Content stays byte-identical but the lag window is where agents trip; payload (not schema) mirrors drift worst (vscode#133).
3. Implementation moves first under pressure (fixtures, muSrs, downstream unblock): #738 local-wins, RFC-003 export, MCP tools, protocol runs, Rust-only cardinality grammar. Charter/ADR-048 now require a Charter Check, but the MCP/WASM tool surface has no spec home so "ahead" cannot even be defined.
4. Tolerance and silent success: ok:true with nothing persisted, unknown fields flattened, missing schema = pass, empty-id accepted. These hide divergence until a human notices (mimicry failure mode; owner rule: repair, not tolerance).
5. Clients re-derive semantics (precedes chain, lifecycle states, type closure, rootInstanceIds fallback) because the core payload lacked a surface at the time; each stays as legacy after the surface lands, so they diverge at the next data-model revision (rev 8 container cutover is the live example).
6. Revisions move faster than docs: data-model revisions 4 to 9 in about six weeks; seeds, skills, CLAUDE.md and test constants repeatedly lag (rows 26-28), and pinned client builds fail by rendering empty.
7. Process fragility for agents: stale local binaries/siblings/shallow clones/long-lived MCP servers give wrong ground truth, and "closed" issues are not proof of merge.
